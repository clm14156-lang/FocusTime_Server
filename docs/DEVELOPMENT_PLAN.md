- 整理日期：2026-11-02
- 更新日期：2026-11-03

- 当前状态：第一至第六阶段代码与本机功能验证完成，测试后端已升级并保留账号、会话和原测试会员。前五阶段原提交 Linux CI 已通过；第六阶段本轮 CI、安装版/物理两机及正式邮件验收仍待执行，第七阶段未开始。

## 1. 实施原则

1. 每个阶段形成可运行、可验证的结果，完成验收后再进入下一阶段。
2. Windows 客户端随阶段接入对应 API，只修改必要的数据来源、命令和权限入口。
3. 保留现有倒计时、悬浮窗、统计、网站代理和程序屏蔽逻辑。
4. 本地记录可靠落盘优先于网络同步，断网不阻塞基本专注使用。
5. 第一版只同步完成的专注记录和必要快照。
6. 后端采用模块化单体，初期一个 API 服务和一个 PostgreSQL 数据库。
7. 支付留待后续，通过受保护的人工发放方式验证会员闭环。
8. 根据用户指令逐阶段开发，范围和验证结果持续记录。

## 3. 阶段 1：后端基础

### 实现内容

- 初始化 ASP.NET Core 10 后端及必要测试项目。
- 在单体内按 Identity、Sessions、FocusSync、Membership 组织模块，明确模块边界。
- 接入 EF Core、Npgsql 和 PostgreSQL，建立可重复执行的迁移流程。
- 固定 /api/v1 前缀、DTO 命名、UTC 时间、记录 ID、分页和错误格式。
- 定义账号、设备、记录、会员及同步契约，提前明确幂等、删除和游标规则。
- 接入配置、结构化日志、traceId、全局异常处理、基本限流和健康检查。
- 输出开发环境启动说明、API 文档和迁移说明。

### 验证方式

- 在开发环境和 Linux 测试环境启动 API。
- 使用独立测试数据库从空库执行迁移，重复执行不破坏数据。
- 检查存活与就绪状态，数据库不可达时返回正确状态。
- 检查参数错误和未处理异常的统一返回格式。

### 验收条件

- [x] 服务可启动，日志和健康检查正常（Windows 发布产物验证）。
- [x] 数据库可迁移，配置中不包含真实生产凭证。
- [x] API 及同步基础契约已记录。
- [x] 未引入 Windows 客户端实现依赖。
- [ ] Linux 实际运行及 CI 验证完成。

本机结果：Release 0 警告 / 0 错误，18 项测试全部通过，含真实 PostgreSQL 迁移；发布产物两次迁移及数据库停机后的 HTTP 健康行为验证通过。完整证据见 [第一阶段验证记录](STAGE1_VALIDATION.md)。

## 4. 阶段 2：注册登录

### 实现内容

- 使用 ASP.NET Core Identity 管理邮箱、密码哈希、安全戳和锁定状态。
- 实现注册验证码请求、验证和账号创建。
- 实现邮箱密码登录、基础设备登记、会话建立、令牌刷新与当前会话退出。
- 从首次实现起处理令牌到期、轮换和撤销，使用服务端令牌摘要存储。
- 实现密码找回、验证码校验、一次性重置凭证和密码重置，重置后撤销旧会话。
- 验证码包含用途、期限、发送频率、尝试次数和原子消费约束。
- 接入客户端 AuthModalViewModel 和现有登录注册弹窗，补充异步状态与错误提示。
- 在实际持有凭证的 Windows 进程中实现安全存储，处理重启恢复登录。

### 验证方式

- WPF 完成真实注册、登录、退出和密码找回闭环。
- 邮箱未验证、验证码错误/过期/重复消费、密码错误、重复注册均返回可处理结果。
- 重启客户端后恢复有效会话，失效凭证要求重新登录。
- 重置密码后原有会话不能继续请求 API。
- 日志中不输出密码、原始验证码和令牌。

### 验收条件

- [x] 生产路径不再依赖硬编码测试账号，旧演示账号仅用于测试替身。
- [x] 现有弹窗已绑定账号闭环，ViewModel 与真实 HTTP/数据库/开发邮件联调通过。
- [x] 登录状态通过当前 Windows 用户 DPAPI 安全恢复和清理，断网退出可持久化重试。
- [x] 认证失败与网络失败有明确反馈，防止重复提交并清理密码输入。
- [ ] 人工逐项点选 WPF 界面、真实 SMTP 邮件送达验证完成。

实现与配置见 [账号认证说明](ACCOUNT_AUTHENTICATION.md)，测试证据与已有客户端失败项见 [第二阶段验证记录](STAGE2_VALIDATION.md)。本阶段复用了设备/会话表的最低必要能力，但未提前实现第三阶段的设备列表与远程管理。

## 5. 阶段 3：多设备管理

### 实现内容

- 生成稳定的安装标识，明确设备与会话不是同一个概念。
- 保存设备名称、系统、客户端版本、首次及最后活动时间。
- 提供设备列表、当前设备标记和会话摘要。
- 实现退出指定会话、退出指定设备全部会话、退出全部设备。
- 每次认证检查会话是否到期或已撤销。
- 完善刷新令牌族的重放检测、并发刷新串行化，以及刷新响应丢失后的有界恢复策略。
- 将 AccountSyncModal 的静态设备内容替换为真实设备集合和操作结果。

### 验证方式

- 两台设备同时登录同一个账号，列表和当前设备标记正确。
- 设备 A 退出设备 B 后，B 的下一次 API 请求被拒绝；A 正常使用。
- 指定设备退出覆盖该设备全部有效会话，其他设备不受影响。
- 修改请求中的用户、设备或会话 ID 不能越权。
- 并发刷新、旧令牌重放和网络重试得到一致、安全的结果。

### 验收条件

- [x] 独立安装实例的多设备登录与远程退出通过真实 API 验证。
- [x] 客户端正确处理会话撤销、凭证清理及设备列表隔离。
- [x] 设备退出只撤销身份会话，不调用历史专注记录删除或结束专注逻辑。
- [x] 安装标识不被当作认证凭证，外账号资源不能操作。
- [ ] 真实两台 Windows 设备界面点选与安装版验证完成。

实现、接口及边界见 [设备会话说明](DEVICE_SESSIONS.md)，测试证据见 [第三阶段验证记录](STAGE3_VALIDATION.md)。

## 6. 阶段 4：专注记录上传

### 实现内容

- 定义兼容 LocalFocusSession 的完成记录 DTO，保留 SessionId、整数秒、UTC 时间和任务快照。
- 为旧本地记录和新增记录增加云端归属及同步元数据。
- 明确首次历史导入的账号归属，避免以后切换账号误上传。
- 补齐普通专注保存失败的反馈和可恢复状态。
- 完成记录与上传操作在同一本地事务内保存。
- 实现固定 operationId、批量上传、服务端唯一约束与幂等处理。
- 增加后台重试、指数退避、逐条确认、错误展示和队列恢复。
- 从本阶段开始保留删除所需元数据，完整双向删除传播在第 5 阶段验收。
- 只上传完成记录和必要快照，不上传运行中会话、完整屏蔽规则或本地设置。

### 验证方式

- 登录后，新完成的普通及强制专注记录都能进入云端。
- 同一操作重复提交多次，服务端只保留一条记录。
- 模拟服务端已提交但客户端未收到响应，重试不产生重复数据。
- 断网完成专注、重启客户端后，队列仍存在并在联网后继续上传。
- 本地服务断连或写入失败时，界面不会把未持久化记录报告为已同步。
- 检查准备时间、实际专注开始时间、时长、自然结束和提前结束的映射。

### 验收条件

- [x] 登录后普通与强制记录上传的基础闭环已通过真实 SQLite/IPC/HTTP/PostgreSQL 验证。
- [x] 网络上传不持有本地保存锁，失败保留本地记录及队列；保存异常明确提示。
- [x] 固定操作 ID 去重、提交后响应丢失重试、数据库重开及普通完成暂存恢复通过验证。
- [x] 原始记录 ID、时间、任务与子任务快照在上传和读回中保持一致。
- [ ] 安装版人工点选、真实两机与 Linux 环境运行验收完成。

实现与边界见 [专注记录上传说明](FOCUS_UPLOAD.md)，证据见 [第四阶段验证记录](STAGE4_VALIDATION.md)。本阶段只保留延后删除元数据，不声称已完成云端删除传播。

## 7. 阶段 5：双向增量同步

### 实现内容

- 使用按用户提交顺序分配的服务器版本和稳定分页边界。
- 实现增量变化查询、历史分页查询和专用批量本地导入。
- 下载记录、删除标记和游标在同一本地事务内提交。
- 实现单条记录删除、删除目标引起的记录删除、删除墓碑和迟到上传处理。
- 同 ID 同内容视为成功，不同内容返回冲突并保留本地数据。
- 实现账号切换时的队列、游标、缓存和记录可见性隔离。
- 覆盖新建后立即删除、删除与上传乱序、正在上传时又发生本地变化等情况。
- 导入历史不标记真实任务完成，不触发新的完成音效或提醒。
- 校正同步界面的范围和真实同步状态。

### 验证方式

- A 创建记录，B 获取；B 删除记录，A 同步后删除，随后旧上传不能复活记录。
- 删除归档目标后，关联记录的删除可以传播，目标和任务本身不进入全量同步。
- 并发写入、分页拉取、进程中断和游标落盘失败不会漏读或误确认。
- 切换账号后不能查看或上传上一账号的云端缓存。
- 历史记录缺少本机目标时可通过快照显示，不自动重建整套目标任务。
- 批量导入不会重复修改本地任务状态或反复触发完成事件。

### 验收条件

- [x] 两个独立设备实例通过真实 SQLite/IPC/HTTP/PostgreSQL 完成双向增量同步。
- [x] 删除不复活、冲突不静默覆盖。
- [x] 账号之间不串记录、队列或游标，切换时立即隐藏旧历史。
- [x] 同步范围仅覆盖约定的专注历史，导入不修改真实任务或触发完成执行。
- [ ] 两台物理 Windows 电脑界面、安装版配套升级及 Linux CI 验收。

实现见 [双向同步说明](FOCUS_SYNCHRONIZATION.md)，证据见 [第五阶段验证记录](STAGE5_VALIDATION.md)。后端 48/48 通过；客户端相关 154 项中 145 通过、9 项既有失败未增加；另 38 项通信恢复回归和 4 项真实联调通过。当前持久测试后端已备份并升级，未替换运行中的客户端进程。

## 8. 阶段 6：会员与权限

### 实现内容

- 实现会员授权记录、有效期、权益版本和受保护的人工发放/续期/撤销入口。
- 提供会员状态和权益查询，接入客户端真实展示。
- 签发绑定账号、设备和会话的非对称签名离线凭证。
- 在本地 Service 校验强制专注和自动屏蔽权限，Desktop 使用同一结果展示状态。
- 区分手动和自动启动来源，保留普通手动专注原有行为。
- 处理离线期限、缓存清理、可信时间、签名密钥轮换和明显时钟回拨。
- 按确定的策略处理运行中会员到期、退出及远程撤销。
- 以稳定 grantId／operationId 为未来支付模块保留关联点，不实现支付和完整订单系统。

### 验证方式

- 普通用户、有效年费、永久会员、过期及撤销用户得到正确权益。
- 修改 UI 状态或直接发起 IPC，不能绕过本地 Service 的正常权限校验。
- 缓存被篡改、签名错误、设备/会话不匹配、凭证过期均拒绝新受限操作。
- 断网有效期内可按策略使用，超过期限后要求联网。
- 已启动专注按约定完成且不能被延长，普通记录保存与同步继续可用。
- 回归现有倒计时、悬浮窗、统计、代理、程序屏蔽和自动规则计算。

### 验收条件

- [x] 会员资格由服务器决定。
- [x] 正常客户端不能仅修改布尔值绕过本地 Service 的权限入口。
- [x] 离线窗口和撤销延迟有明确文档：最长 72 小时，并受会员/会话绝对期限约束。
- [x] 四项核心需求形成本机功能闭环。
- [ ] 安装版配套升级、物理两机界面及本轮 Linux CI 验收。

实现见 [会员说明](MEMBERSHIP.md)，证据见 [第六阶段验证记录](STAGE6_VALIDATION.md)。后端 63/63、25 项会员安全及真实双客户端会员联调通过；219 项客户端相关回归保留同样 9 项旧失败。本机已备份升级并导入原测试会员；Desktop/Agent/Service 未被强制重启。

## 9. 阶段 7：部署与上线验证

### 实现内容

- 部署到受支持的 Linux 环境，配置 Nginx、HTTPS、Kestrel 和 systemd。
- 使用受限应用账号，限制数据库网络访问和凭证权限。
- 持久化必要密钥，配置密钥轮换、日志脱敏和环境配置。
- 完善登录、邮件、刷新和同步的限流及请求大小限制。
- 建立数据库备份、恢复验证、发布回滚和迁移执行流程。
- 配置健康检查、异常观测、基础告警和故障排查说明。
- 执行客户端与云端完整回归及异常场景验证。

### 验证方式

- 通过正式 HTTPS 入口完成注册、登录、设备退出、双向同步和会员验证。
- 服务和数据库重启后，数据、令牌策略及签名能力保持正确。
- 模拟断网、数据库不可达、超时、邮件失败、重复请求和令牌过期。
- 覆盖客户端系统代理、VPN 和 API 不可达场景。
- 从备份恢复到独立环境，确认账号、记录和会员数据可用。
- 验证生产日志不包含密码、验证码、原始令牌或多余隐私数据。

### 验收条件

- [ ] 生产部署和恢复操作有可执行说明。
- [ ] HTTPS、限流、健康检查、日志和备份验证通过。
- [ ] 七阶段功能完成联调与回归。
- [ ] 遗留问题、产品策略和运行限制均已记录。
