# 管理员调整会员

## 接口与权限

- `GET /api/v1/admin/users/{userId}/membership-adjustments`：真实用户资料、当前权益、赠送范围撤销效果、可操作范围及保护说明。
- `POST .../preview`：`operationId`、`action=grant|revoke`、`plan=monthly|annual|lifetime`（发放时）、`scope=all|admin-gifts`（撤销时）、`reasonCode`、`note`。返回服务端计算的前后权益及五分钟内有效的确认方案。仅保存待确认记录，不更改会员资格。
- `POST .../apply`：只接收 `operationId`，执行已保存的确认方案。不接受客户端指定有效期、目标授权ID、退款核验标志等覆盖参数。

以上接口复用 `Administrator` 白名单策略。写入还要求 `X-FocusTime-Admin: 1`，并在事务中重新校验管理员当前登录会话。按操作人与目标用户的固定顺序取得现有账号事务锁，与原有订单发放/CLI会员管理互斥。

## 发放规则

月会员增加30天，年会员增加365天，永久会员无到期时间。限期赠送沿用订单发放规则：以当前生效且未撤销的限期授权中最晚的到期时间为基准，没有则从服务器当前时间起计算。新增独立授权，不覆盖原授权。

已有永久权益继续有效。手动赠送不会插入、更新或伪造支付订单。所有理由固定白名单；备注最多400字符。发放原因：用户补偿、活动赠送、免费体验、内部测试。

## 撤销保护

只有本模块已成功发放的记录所指向的授权，且没有任何订单关联，才被识别为可撤销的管理员赠送。购买授权、旧导入授权、无法确认来源的授权，均不会被赠送范围撤销匹配。

“撤销全部”仅允许当前所有未过期、未撤销的授权都是可验证管理员赠送的情况。当前架构没有退款状态及独立付费权益撤销权限模型，遇到购买或未知来源权益返回409 `paid_or_unknown_entitlements_protected`，不执行撤销。选择“用户申请退款”只是操作原因，绝不代表退款证明，也不会触发退款。

“仅撤销管理员赠送”逐条撤销已确认来源的赠送授权，保留购买授权的原始日期和状态。不存在有效会员时不提供撤销表单；没有可撤赠送时确认按钮不可用。选择“其他原因”必须填写非空备注。

服务端资格和版本立即更新。现有签名离线授权最长72小时，并受会话和原权益到期时间约束；已签发离线凭证按既有客户端策略失效，不在本次改动中改变租约或强制退出设备。

## 防重、并发与审计

迁移 `20261106145339_AdminMembershipAdjustments` 新增 `membership.admin_adjustments`。该表保存待确认方案、请求哈希、来源授权、前后快照、目标授权ID和成功结果，并对操作ID、赠送授权ID建立唯一约束。

同一操作ID和相同请求重复预览/提交返回原结果，不重复发放或撤销；同一ID用于不同账号、不同操作人或不同参数会被拒绝。确认方案归属发起管理员，五分钟失效。执行前比较权益版本、授权集合及来源指纹；确认后发生变化须重新预览，不自动改变用户已确认的方案。

实际变更复用 `MembershipService.StageChangeAsync`。授权、版本、会员审计及确认回执在同一事务提交。任何保存失败均回滚，不出现已发放但无日志的状态。

用户操作日志按已应用的确认回执展示一条人类操作记录，操作人解析为真实管理员邮箱，保留原因和备注。内部逐授权审计仍保存在原会员审计表，但不重复展示。未确认/过期方案不伪造成操作成功日志。

## 发布与验证

先备份数据库，应用上述增量迁移，再启动含新接口的构建。迁移只增加确认记录表和索引，不回填或改写原订单、用户或会员授权。

本地集成验证使用独立 `focustime_test_*` 临时库，覆盖权限/会话校验、并发重复提交、用户与操作人隔离、有效期叠加、付费和未知来源保护、多赠送撤销、其他原因必填、过期/变更方案拒绝，以及回执保存失败时的整体回滚。测试源码和产物依 AGENTS.md 仅留在本地。
