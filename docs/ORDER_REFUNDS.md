# 订单退款（72 小时）

## 接口及规则

`GET /api/v1/admin/orders`、单条详情和导出返回 `refund` 元数据：支付完成时间加 72 小时的截止时间、期限资格、渠道支持状态、可撤销权益状态，以及真实退款回执。`order.serverTimeUtc` 用于前端时钟校准；界面根据服务器时间加单调计时更新，超过截止时间后自动禁用。

`POST /api/v1/admin/orders/{id}/refund` 沿用管理员白名单、现有会话和 `X-FocusTime-Admin: 1`。请求包含 operationId、amountFen（整数分）、reasonCode、note（可选，最多 200 字符）、revokeMembership。金额必须大于 0 且不超过原支付金额，默认全额；每个订单只接受一笔退款，较小金额会按实际退款金额记录，不能再提交剩余金额。

以已保存的 PaidAtUtc 为起点，服务器时刻 <= PaidAtUtc + 72 小时才允许首次退款。未支付、时间异常、退款中、已退款、超过期限的订单拒绝新退款；同一管理员用同一 operationId 和原内容重试已成功请求可读取原回执，包括期限过后。不同内容、账号、订单不能复用 operationId。

## 支付渠道边界

目前只有 Development/Testing 中、已保存 simulation 支付凭证的订单可完成模拟退款。界面明确提示不会发生实际资金划转，事件为“模拟退款已确认”。未接入的真实微信/支付宝或其他渠道返回 refund_provider_not_supported，不会生成成功退款、不撤销权益、不伪造渠道回执。接入真实支付渠道后，必须以可核验的渠道结果扩展本服务，不能仅修改数据库就宣称资金退款成功。

## 原子性及权益

服务按管理员与订单所属用户的统一账号锁顺序重新验证登录会话。退款回执、订单 refunded 状态、处理事件、操作审计以及可选的会员撤销与版本更新在同一事务提交；失败全部回滚。数据库为 OrderId 建唯一索引，服务另做请求哈希及归属校验，防止重试或并发重复退款。

只撤销该订单 MembershipGrantId 绑定且属于同一用户的授权；若授权被另一订单共用或关联无法核实，拒绝自动撤销。不会撤销全部会员、其他订单或管理员赠送的权益，也不重算其他授权的时长。没有实际撤销就不生成撤销事件。不勾选时保留原权益和会员版本，关联会员的来源仍显示订单购买。

会员服务沿用现有版本与离线签名授权策略：客户端联网同步后获取新权益，已签发离线授权仍遵循原有租期策略。

## 迁移及验证

增量迁移 `20261108175329_OrderRefunds` 创建 membership.order_refunds 及索引，并扩展原订单支付/开通约束以保存退款状态；不修改现存订单金额、支付时间或会员授权。部署前备份原数据库，再执行该迁移并重启后端。

本地隔离 PostgreSQL 测试覆盖权限、支付时间及 72 小时边界、全额/部分退款、保持权益/定向撤销、共享授权拒绝撤销、并发与幂等、审计去重和持久化失败回滚。组件检查覆盖自动到期、输入校验、失败重试同一操作号、列表/详情/统计和时间轴更新。测试代码和产物留在本地，不提交或推送。
