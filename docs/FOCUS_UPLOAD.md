# 第四阶段：专注记录上传

本文保留第四阶段交付时的范围。第五阶段已开放下载及删除传播，当前行为以 [双向同步说明](FOCUS_SYNCHRONIZATION.md) 为准；下文“未开放”“延后删除”等描述属于第四阶段历史状态。

更新日期：2026-11-03。本阶段实现本机完成记录向云端上传；多设备下载、增量拉取和删除传播仍在第五阶段。沿用现有专注模型、SQLite、本地服务及 Windows 弹窗，不迁移屏蔽规则或全部本地数据。

## 数据与进程边界

本地服务继续按真实 Windows SID 管理 SQLite，保存专注记录、任务快照、归属和上传队列。桌面进程持有 DPAPI 保护的云端凭证，通过 HTTP 上传；令牌、密码不会经 Named Pipe 传入服务。

专注首次落盘时确定归属。桌面启动请求附带当前本地绑定标识；未登录或尚未登记的开始请求明确保持未归属。普通与强制专注后续更新保留原归属，因此 A 开始的记录不会因为完成时登录了 B 而上传到 B。绑定还区分 API 地址，避免把另一个服务器的队列发送到当前服务器。

后台自动启动可使用最近登记且未过期的一分钟账号上下文；桌面正常运行时每 15 秒续期。无有效上下文时保持未归属，不凭旧缓存猜测账号。已开始记录的归属不受续期或退出影响。桌面关闭后，本地服务仍可完成已归属的强制专注，网络上传在下次打开客户端后继续。

## 本地可靠保存

SQLite 迁移从 v14 升到 **v15**，沿用原初始化器的迁移前备份，新增：

| 表 | 用途 |
| --- | --- |
| `focus_sync_bindings` | 用户 ID、API 地址摘要与本机绑定标识；不含凭证 |
| `focus_sync_context` | 当前后台创建记录可用的短期归属上下文 |
| `focus_sync_owners` | 每个记录固定的归属、当前载荷摘要、已知服务器版本与删除标记 |
| `focus_sync_outbox` | 固定 operationId、记录 ID、快照、状态、尝试次数、下次尝试时间、错误及确认版本 |

完成记录、任务快照、归属和待上传操作在同一事务内提交。队列写入失败会回滚本次保存，不能出现“记录已保存但没有上传任务”的假成功。重复保存相同快照复用操作 ID；变更产生新操作，旧操作的迟到确认不会清掉新操作。

普通专注如果本地服务不可达或写入失败，先将完成 DTO 原子暂存到 `%LOCALAPPDATA%/FocusApp/RecordRecovery/`。保留原记录 ID、开始时归属及快照，重连和重启后重试，服务确认保存后才清除暂存。磁盘写入也失败时在内存保留并提示保持窗口、重试保存；不能承诺磁盘故障后关闭进程仍可恢复。

损坏暂存移为 `.invalid.<随机ID>` 保留，提示检查，不阻塞其他记录。暂存只有专注记录，没有认证信息，使用当前 Windows 用户目录的本地保护边界。本地保存异常优先显示在主窗口和云端状态页，不显示为上传完成。

## 首次历史导入与账号切换

迁移前记录以及未登录时开始的记录默认未归属。账号页显示本批最多 200 条未归属的已完成记录；用户先准备导入，再确认显示的账号和数量。只分配确认过的记录 ID，不自动认领所有历史。

确认时再次检查记录仍存在、未删除、未分配且快照未变化。已归属 A 的记录不能由 B 重新认领；切换账号会取消旧确认，并隔离读取和确认队列。普通专注保存恢复时如果开始阶段没有取得有效绑定，记录仍保留未归属，需要确认历史导入。

本阶段保留原本按 Windows 用户显示的本地统计视图，未重构所有历史记录的可见性。这里实现的是上传归属隔离；第五阶段继续完善账号切换下的云端缓存、下载与可见性。

## API

两个接口均需 Bearer 认证、禁止缓存。服务器从认证会话确定账号和来源设备，忽略客户端自行声明的所有者。

| 方法 | 路径 | 内容 |
| --- | --- | --- |
| POST | `/api/v1/sync/focus-records/push` | `operations`，最多 200 项；客户端每批最多 50 项并限制字节大小 |
| GET | `/api/v1/focus-records/{recordId}` | 读取本账号单条已上传记录，供核验；不是自动下载/导入流程 |

操作包含 `operationId, recordId, kind=upsert, record, baseRevision=null`。`recordId` 保留原 LocalFocusSession.SessionId；记录只有时长、UTC 时间、结束方式、模式、目标/任务快照、屏蔽启用标记及自动规则标识，不上传屏蔽列表、应用路径或设置。

响应逐项返回 `operationId, recordId, status, serverRevision, code`。`status` 是 `applied / duplicate / conflict / rejected`。正常可解析的批次即使部分冲突仍返回 HTTP 200；外层格式、认证、大小与限流问题使用统一 Problem Details。

同账号同操作 ID、同规范化内容返回原结果；改变操作内容返回 `operation_id_reused`。同记录 ID 同快照为重复成功；不同内容返回 `record_conflict` 并保留原云端历史。本版完成记录不自动覆盖或合并。

时间统一 UTC、任务按排序值和任务 ID 规范化后计算摘要，JSON 属性顺序和等价时区不会制造新记录。保留强制专注准备阶段提前结束时的未来计划开始时间，实际秒数为零。异常时长、时间顺序、重复任务、过大快照和不支持的文本逐项拒绝，不阻塞同批正常记录。

## 云端存储与一致性

迁移 `20261103042017_FocusRecordUpload` 新增 `focus.records`、`focus.sync_states`、`focus.receipts`。记录主键为用户与记录 ID，收据主键为用户与操作 ID。保存服务端来源设备、规范化载荷及摘要、收到时间和版本。

同账号上传与登录、刷新、撤销共用事务锁，锁内重新确认会话。记录、逐项收据和每账号版本计数一起提交；相同批次内重复操作也去重。只有实际新增记录分配下一版本，为第五阶段保留按提交顺序的基础。响应丢失后重传原操作，不分配新记录或新版本。

## 重试与确认

桌面运行时每 15 秒检查本地队列，只有已落盘完成记录可进入上传。普通重试退避为 5、10、20、40 秒等，最多 300 秒，受检查周期影响；限流至少等待 60 秒。尝试次数与下次时间落盘，重启保留。手动“立即上传 / 重试”可清除当前账号待重试项的等待时间。

网络请求在本地事务之外进行，云端慢或不可用不持有本地保存锁。账号和 API 地址在发送前及认证重试时核对；刷新或账号切换不能把 A 的批次改用 B 的凭证发送。

客户端核对返回的操作 ID、记录 ID、数量、状态和成功版本，缺项、错项或无效确认不会清除本地队列。已应用/重复成功才标记确认；冲突或拒绝保留原本地记录并显示需处理，不能凭 HTTP 200 将整个批次当作成功。

## 删除与第五阶段边界

本地删除记录或删除目标时，在同一事务保留记录 ID、归属、已知版本和稳定的延后删除操作，停止发送待上传旧快照。迟到确认不清除删除标记，旧完成重试也不能在本机重新创建已删除记录。

**本阶段不会删除已有云端记录。** 上传接口对 `kind=delete` 明确返回 `delete_not_available`，客户端不发送延后删除操作。云端墓碑、下载游标及完整删除传播在第五阶段实现，不能把保留删除标记当成云端已删除。
